## 1. Fix account enrollment, session recovery and the API client

**Start in the existing code.** `src/types/api.ts` requires a string token and a user on every auth response. `auth-provider.tsx` installs that response after registration and `auth-card.tsx` redirects to the feed. `services/auth.ts` currently resends verification with a token and no email. Fix these paths before protecting new pages with the existing route guard.

| Server result | Browser action |
| --- | --- |
| Registration | Fetch `GET /policies`. Link the returned policy URLs to the matching published text. Collect `date_of_birth` as `YYYY-MM-DD` for the 18+ pilot and submit `accepted_policies` as a map of policy name to displayed version for terms, privacy and community. Marketing is optional. Send these with the existing credentials to `POST /auth/register`. A 201 with `token: null` goes to “check your email.” Resend using public `POST /auth/email/verification-notification` with `{email}`. |
| Enrollment incomplete | Password or Google login can return `onboarding_required: true`, a one-use, ten-minute `onboarding_token`, and no JWT or user. Collect DOB and current acceptances, then call `POST /auth/onboarding` with that token in the body. Restart sign-in if it expires. Keep pending enrollment separate from persistent sessions. |
| Active account | Install the bearer token and its expiry. Restore using `GET /auth/me`, serialize token rotation through `POST /auth/token/refresh`, and retire the old token and Relay connection together. Keep forgot/reset password, authenticated profile edits via `PUT /auth/profile`, and `PUT /auth/password` with current password and confirmation. Upload a profile photo using `POST /uploads/avatar`, then attach its returned `avatar_url` to the account. Artist images use a different field in Step 3. Model the public profile separately from private account email, verification and linked identities. |
| Verified restricted account | Persist `restricted_access: true` with the session. Route directly to recovery on sign-in and reload. Active-only calls such as `/auth/me`, token refresh and entitlements cannot bootstrap this screen. Allow own privacy requests, policy acceptance, own report status/decisions/appeals, logout and the limited billing operations in Step 4. A valid restricted session must survive a 403. Keep a route back to sign-in when expiry or an account-status change requires a new session. An action-level 403 alone does not identify a suspended user. |

**Transport and caching.** Keep `services/api.ts` as the JSON entry point. Preserve field errors, allow custom headers, handle 204 without a body, and give media/downloads and raw Relay authorization their own response handling. Type page-number and cursor results separately. Keep existing page-based feeds working. If using feed cursor mode, start with `pagination=cursor`, follow `meta.next_cursor` while `has_more`, and restart on a 410 expiry. Never carry a cursor across viewers or filters. Include viewer ID in personalized query keys, including liked/saved/profile keys currently scoped only to “auth.” On account change, logout or deletion, cancel outstanding requests, clear private cache entries and retire subscriptions. Only a 401 for the current bearer should clear that session. Configure invalidation on foreground and token change explicitly because the current query provider disables automatic refetch on window focus.

**Privacy and appeals.** Add Settings actions for current policy acceptance (`POST /me/policy-acceptances`), export and deletion. For a sensitive action call `POST /auth/reauthenticate` with `purpose: export_data` or `delete_account` and the password or a fresh linked Google token. Support `mfa_code` where required. Send the five-minute, session-bound, one-use proof in `X-Reauth-Proof` to `POST /me/export-requests` or `POST /me/deletion-requests`. Poll `GET /me/export-requests/{export}`, then fetch the issued signed `download_url` with the same owner’s bearer. On accepted deletion, show the reference and clear the session immediately. Implement the public web page `/delete-account` for email requests and explicit confirmation of the emailed token via `POST /account/deletion-requests` and `POST /account/deletion-confirmations`. Keep email responses generic. Show own report status, decisions and appeals using `/me/reports/{report}`, `/me/moderation-decisions` and `/me/moderation-appeals`. An appeal submits `decision_id` and `explanation`. Preserve a pending/ready/failed/expired export state. Re-read the status for a fresh signed download link while the export remains ready, and offer a new authorized export after expiry. An accepted deletion revokes access immediately while cleanup runs.

**Acceptance.** Walk through a new email signup, verification/resend, Google enrollment, an existing active account and a suspended account in a fresh browser tab. Reject an underage DOB and stale policy version, recover from an expired export proof, and switch users without showing the previous account’s data. ## 4. Deliver web billing and private release scheduling

### Stripe subscription journey

1. Add pricing, billing settings and return/cancel pages to the customer origin. Read `GET /plans` for each offer’s amount in minor units, currency, interval, `offer_version`, `checkout_enabled`, environment and disclosures. The launch paid offers are **Artist Starter at USD 4.99/month** and **Artist Pro at USD 19.99/month**. Gate purchase by artist enrollment, enabled offer and environment. Clearly identify test purchases. Use server gates for live sales.
2. For one confirmed purchase, persist an account-scoped UUID and exact input **before** calling `POST /billing/checkout` with `{plan_code, offer_version}` and `Idempotency-Key`. Save the returned local `reference` before navigating to the hosted `url`. On a timeout, replay the same key and payload. For stale terms, refetch the catalog and obtain a fresh choice. Prevent overlapping purchases, including double-click and reload. If reconciliation is required, keep the attempt/reference visible with a pending or support state. Generating a new key on a provider conflict can start a second operation.
3. On return, read the appended `reference`. On the cancel page or after a lost tab, recover the saved reference. Poll `GET /billing/checkouts/{reference}` with the owner token and bounded backoff. Distinguish a pending/expired checkout from a completed checkout awaiting payment reconciliation. Show processing while access is pending. Refresh `/me/subscription` and `/me/entitlements` before unlocking tools. Only verified paid invoice periods grant access. The cancel return can arrive without a reference query parameter and a completed checkout can lack active access. Test both cases and keep retry bounded. Stripe sends signed events to the backend webhook.
4. In billing settings, show `effective_plan`, `paid_through`, `cancel_at_period_end` and `renewal_pending`. Use `POST /billing/portal` for the hosted portal, `GET /me/billing/invoices` for paged invoices and issued `receipt_url` links, and `POST /billing/subscription/cancel` or `/billing/subscription/resume` for renewal. Cancellation preserves verified time. Resume applies before the subscription ends. During `renewal_pending`, disable conflicting renewal actions and refresh local subscription state. On portal return refetch subscription, entitlements and invoices. A plan change requires the existing subscription and paid period to end before a new checkout. Restricted owners may read subscription, invoices and checkout status and cancel renewal. Checkout creation, portal and resume require active access.

### Artist release journey

1. Offer “Post now” to free creators and “Save as draft” in the artist workspace. Decide intent **before uploading bytes**. For drafts, send `publication_intent: "draft"` to signed-url negotiation, multipart fallback or every chunk and completion, and again to `POST /videos` with the current rights confirmation. Keep the same UUID, filename, MIME type, total byte/chunk counts and intent across chunk/complete. Chunks use zero-based indexes and a maximum 2 MiB per part. Completion consumes the manifest. If its reply is lost and the session is gone, restart with a new upload ID before creating a video. A draft can return `video_url: null`. Use its private storage reference and server-generated cover. Switching an already uploaded immediate file to draft requires a new private upload.
2. Read `GET /me/artist/releases` and owner detail. Model `processing_state` (processing/ready/failed) separately from `publication_state` (draft/scheduled/published), plus `moderation_status`, `error_code` and `version`. For interrupted or failed encoding use `POST /me/videos/{video}/retry` when eligible. For an uncertain create response, reconcile the owner’s posts before offering another submission.
3. Fetch issued owner preview URLs with bearer authorization. For local media, use authenticated fetch and an object URL for bounded previews, or an authenticated streaming path supporting byte ranges. A plain video tag cannot add the bearer header. Handle the private S3 redirect without forwarding the JWT to storage. Preserve signatures on issued media URLs, refresh expired URLs from the resource, and exclude private media from shared caches and image optimization. Also exercise the issued `GET /media/{token}` URLs for **published** local media. A valid signature is still subject to viewer visibility. Use the viewer’s credentials for follower/private access on the trusted API origin. Test owner, follower, guest and recently blocked viewer, including seek (206), expired/denied URL (404) and a refreshed URL from the resource. A paused schedule returns to draft with a reason and needs an explicit owner decision. Delete an owned draft/release with the existing `DELETE /videos/{video}`, then refresh both posts and releases.

## 5. Add the inbox, artist updates and Relay

1. **Build text chat over REST first.** Add an inbox and conversation page. `POST /conversations` with the other account’s `recipient_user_id` opens the canonical conversation. Sending requires mutual follows, both parties allowing messages and no block. Honor `can_send` while preserving available participant history. Send `{body, client_message_id}` to `POST /conversations/{conversation}/messages` with one sender-generated UUID per message. An exact retry returns the same message (201 first, 200 replay). Use cursor pagination for the inbox, `before_id` for descending history, and `after_id` for ascending catch-up until `has_more` clears. Merge by message ID. Only mark displayed messages via `PATCH /conversations/{conversation}/read` with `last_read_message_id`. Set `muted` via `PATCH /conversations/{conversation}/preferences`. Inbox items expose `recipient_user_id` and can lack a name/avatar. Use a known profile or a neutral label until resolved. User profile reads take a username. Avoid treating a numeric ID as a username or scanning users to infer it.
2. **Collect separate artist-update consent.** Read `GET /artists/{artist}/update-subscription` for the viewer’s actual state and `current_consent_version`. The convenience fields on the current artist card are placeholders. The endpoint supplies a version. Bundle or retrieve approved wording for that version. If the wording is unavailable, disable new opt-ins while preserving opt-out. Use an initially unchecked choice for new subscribers. PUT `{subscribed: true, consent_version}` on affirmative opt-in, or `{subscribed: false}` on opt-out. No follow or purchase is required. Expose global controls through GET/PATCH `/me/communication-preferences` for direct messages, message alerts, muting new conversations and artist updates. [Artist resource](../app/Http/Resources/ArtistResource.php) · [Consent endpoint](../app/Http/Controllers/Api/V1/CommunicationController.php)
3. **Deliver announcements and activity.** Pro owners can list, create, edit or delete drafts under `/me/artist/announcements`. Accept plain text (title up to 120 characters, body up to 2,000) and optional owned eligible public `video_id`. Reject markup/external links. A downgraded owner can still inspect history and delete an unsent draft. Edit with the returned version. A separate `POST /me/artist/announcements/{announcement}/send` takes `{version}` and a durable `Idempotency-Key`. A 202 means queued. Show owner estimates and delivered/suppressed counts. Baseline quota is four sends per paid period, up to 1,000 eligible recipients per send. Explain a quota-specific 429 and an oversized-audience 422 without automatically retrying the send. Fans read delivered items via `/me/announcements`, detail and explicit `PATCH /me/announcements/{announcement}/read`. In Activity, support `direct_message`, `artist_announcement` and `release_paused` destinations and redacted items. Replace the first-page scan in `activity-unread-dot.tsx` with `GET /notifications/unread-count`. Chat’s unread badge comes from conversation metadata. Refresh the linked announcement and alert when either is marked read. Marking notifications read does not advance a chat read cursor. Preserve grouped activity reads and add a “Clear read activity” action via `DELETE /notifications/clear-all`.
4. **Add one Relay connection per active browser session.** `POST /realtime/session` returns connection settings, public key, channel, auth URL and expiry. Connect via Pusher protocol 7, then authorize the real socket ID and exact returned channel with the current bearer at `POST /broadcasting/auth`. It returns raw `{auth}`. Subscribe successfully **before** loading initial REST state. Keep the JWT on the trusted API auth request. `event_id` is an opaque string, and the `message.created` version belongs to the conversation. Use the last actual message ID for REST catch-up. On reconnect, visibility return, token rotation or a gap, recover via REST and catch up messages from the last ID. Deduplicate by `event_id`, track versions by resource and handle out-of-order hints. When Relay is unavailable, retain sending/reading over REST and use bounded foreground polling. Never send messages over the socket.

| Relay hint | Refresh in the browser |
| --- | --- |
| `message.created`, `conversation.updated` | Inbox/unread state and active thread. The first hint identifies a message, the second a conversation. Resolve the thread through REST. |
| `notification.created`, `notifications.updated` | Activity list and count. Reload the relevant announcement or release when opened. |
| `release.updated`, `entitlements.updated` | Owner release detail/list, or capabilities, subscription and affected credit displays. |
| `boost.updated`, `placement.updated` | Owner campaign/detail, balance/ledger, or placements and pending extension consent. |
